# Tech Verse — Firestore Security Rules: অডিট রিপোর্ট ও ডিপ্লয়-গাইড

প্রজেক্ট: `tvsitesofficial` · ডেটা-নেমস্পেস: `tvProject/main/**` · ফাইল: `firestore.rules` (৬৯৭ লাইন, ৭৮টা `allow`)

> ⚠️ **ডিপ্লয়ের আগে ৩টা জিনিস:** (১) Console-এর বর্তমান rules কপি করে ফাইলে রাখুন (rollback)। (২) `tvsitesofficial`-এ অন্য কোনো অ্যাপ/সাইট (কোর্স, এক্সাম ইত্যাদি) root-কালেকশন ব্যবহার করলে এই rules সেগুলো **বন্ধ করে দেবে** — একটা Firestore ডেটাবেসে একটাই rules চলে। (৩) প্রথম অ্যাডমিন ও ডিফল্ট ক্যাটাগরি বসানো না হলে অ্যাডমিন-প্যানেল/কমিউনিটি-পোস্ট চলবে না (ধাপ ৯.৬, ৯.৭)।

## ৩) গুরুত্বপূর্ণ ভ্যালিডেশন

- **প্রোফাইল তৈরি:** ডক-id = নিজের uid; ঠিক ৬ ফিল্ড; `isAdmin == false`; `createdAt == request.time`; `email` অথ-টোকেনের ইমেইলের সাথে মিলতে হবে (বড়/ছোট হাত উপেক্ষা; টোকেনে ইমেইল না থাকলে `""`) — অন্যের ইমেইল বসিয়ে অ্যাডমিনকে ধোঁকা দেওয়া ঠেকায়; `photoURL` ফাঁকা বা `https://`।
- **প্রোফাইল এডিট (`setDoc(...,{merge:true})` নিরাপদ):** যাচাই হয় *পরিবর্তিত ফিল্ড* (`diff().affectedKeys()`), তাই এডিটের আড়ালে `isAdmin` ইত্যাদি লুকানো যায় না; পুরোনো/মাইগ্রেট করা প্রোফাইল (বাড়তি ফিল্ড/ফিল্ড-না-থাকা) ও চলে। `avatarData` = ফাঁকা বা ≤১৬০,০০০ অক্ষরের image data-URL; `avatarThumb` = ফাঁকা | ≤১২,০০০ data-URL | Google/GitHub অবতার URL (≤৫০০)।
- **বুকিং:** ঠিক ১০ ফিল্ড; টাইপ + দৈর্ঘ্য (নাম ১–১২০, ইমেইল ≤২৫৪ ও `x@y` প্যাটার্ন, ফোন ≤৪০, বিস্তারিত ≤৫০০০); `status` = `BOOKING_STATUSES[0]` (`নতুন`); `createdAt == request.time`; গেস্টের `uid` অবশ্যই `null`, লগইন-করার `uid` অবশ্যই নিজের।
- **কন্টেন্ট (৮টা):** create = ফর্ম/সিডের ঠিক ফিল্ড-সেট + `order`; update = শুধু যা বদলাচ্ছে তা যাচাই (টাইপ, দৈর্ঘ্য, `http(s)` URL, `category ∈ {web,pwa,design}`, `featured` bool, `features` list ≤৪০, `value`/`order` number)।
- **আলোচনা তৈরি:** ঠিক ১৩ ফিল্ড; `uid`, `authorName`, `authorAvatar` সার্ভারে থাকা প্রোফাইলের সাথে মেলে; `title` ৩–১২০, `body` ৩–৫০০০ (`LIMITS`); ক্যাটাগরি **বিদ্যমান ও active**; `status=active`, `createdAt/updatedAt=request.time`, `editedAt=null`, `likedBy=[]`, `likeCount=0`, `replyCount=0`; `replySyncId`/মডারেশন-ফিল্ড ক্লায়েন্ট বসাতে পারে না।
- **লাইক:** শুধু `{likedBy, likeCount}` বদলায়; কলার ঠিক নিজের uid যোগ/বাদ দেয়, বাকি সব অপরিবর্তিত (সাবসেট-চেক + সাইজ ±১); `likeCount == likedBy.size()`; সর্বোচ্চ ৫০০০; শুধু active কনটেন্টে (রিপ্লাইয়ের ক্ষেত্রে parent-ও active); ব্লকড পারে না।
- **রিপ্লাই + `replyCount` (atomic batch):** রিপ্লাই তৈরি/মালিকের মুছা/অ্যাডমিন-মডারেশন — প্রতিটাতে reply-ডক আর parent-এর `{replyCount, replySyncId}` **দুই দিক থেকে** (`getAfter`/`existsAfter`/`exists`) যাচাই হয়: ঠিক ±১, `replySyncId` = ওই রিপ্লাইয়ের id, রিপ্লাইটা এই batch-এ নতুন/বদলানো। তাই "রিপ্লাই ছাড়া কাউন্ট বদল", "কাউন্ট ছাড়া রিপ্লাই", দুটো রিপ্লাইয়ে একটা +১, ভুল id, অন্য আলোচনার কাউন্ট বাড়ানো — সব বাতিল। `replyToId/replyToName` থাকলে টার্গেট রিপ্লাই **active ও লেখকের নাম মিলতে হবে** (লুকানো রিপ্লাইয়ের লেখকের নাম ফাঁস হয় না)।
- **রিপোর্ট:** id = `{reporterUid}_{targetType}_{targetId}` (`setDoc` দ্বিতীয়বার = update ⇒ শুধু অ্যাডমিন, তাই overwrite/duplicate অসম্ভব); `reason` ছয়টার একটা; `details ≤ ৫০০`; লক্ষ্য discussion/reply থাকতে হবে; `status=open`; ব্লকড পারে না। রিভিউ: `reviewedBy = নিজের uid`, `reviewedAt = request.time`, status ∈ `open|reviewing|resolved|dismissed`।
- **ক্যাটাগরি:** id = slug `[a-z0-9-]{1,40}`; `name` ১–৪০; `order` সংখ্যা ০–৯৯৯৯; `active` bool; `createdAt = request.time`।
- **কমিউনিটি-ব্লক:** `communityBlocked == true` হলে নতুন আলোচনা/রিপ্লাই/লাইক/রিপোর্ট/এডিট বাতিল — কিন্তু সাইটের বাকি সবকিছু (কন্টেন্ট পড়া, বুকিং, প্রোফাইল এডিট) এবং **নিজের কনটেন্ট soft-delete** চলে।

## ৪) বাস্তব কোয়েরি ↔ rules (rules কোয়েরির ফলাফল ফিল্টার করে না)

| কোয়েরি (কোড) | rules-এর শর্ত | ফল |
|---|---|---|
| `content.js` — `orderBy(order)` সব ৮ কালেকশন (limit নেই) | `allow get, list: if true` | ✅ সাইট ভাঙে না |
| ফিড — `where(status=="active")[, category]` + `orderBy` + `limit(20)` + `startAfter` | `status=='active'` ও `limit ≤ 50` | ✅ (পেজ-সাইজ ২০) |
| রিপ্লাই — `where(status=="active")` + `limit(30)` | active + parent active + `limit ≤ 50` | ✅ |
| ক্যাটাগরি — `orderBy(order)` + `limit(50)` | `limit ≤ 50` | ✅ |
| নিজের বুকিং — `where(uid==নিজের)` + `orderBy(createdAt)` | `resource.data.uid == auth.uid` | ✅ |
| অ্যাডমিন: বুকিং `limit(300)`, ইউজার, রিপোর্ট `limit(25)`, আলোচনা (স্ট্যাটাস-ফিল্টারসহ/ছাড়া), রিপ্লাই `limit(50)` (ফিল্টার ছাড়া), `getCountFromServer` | `isAdmin()` | ✅ |
| `status`-ফিল্টার ছাড়া / `limit` ছাড়া / `limit>50` পাবলিক কোয়েরি | — | ❌ (ইচ্ছাকৃত) |

কোনো ক্লায়েন্ট-কোয়েরি বদলানোর দরকার হয়নি। ইনডেক্স-ফাইল (৫টা কম্পোজিট) সব কোয়েরি ঢাকে।

## ৫) অডিটে পাওয়া বিষয় ও সিদ্ধান্ত

1. **[কোড বদলানো হয়েছে] সিড-batch ও Rules-এর ২০-access-call সীমা।** অ্যাডমিন-ড্যাশবোর্ডের "ডিফল্ট কন্টেন্ট বসান" আগে একটাই batch-এ সর্বোচ্চ ৩৫টা লেখা পাঠাত; প্রতিটা লেখায় `isAdmin()`-এর জন্য ১টা `get()` যায়, আর Firestore একটা batch-এ সর্বোচ্চ ২০টা document-access-call দেয় (ক্যাশিংয়ের ওপর ভরসা করা অনিশ্চিত)। তাই `js/admin.js → runSeed()` এখন ≤১৫টা লেখার ভাগে commit করে; এক টাইপের সব আইটেম একই ভাগে থাকে (আধা-সিড হয় না)। সিনারিও-টেস্টে বাস্তব `seed-data.js` দিয়ে প্রতিটা ভাগ যাচাই করা।
2. **Rules স্প্যাম/রেট-লিমিট ঠেকাতে পারে না।** গেস্ট-বুকিং ও কমিউনিটি-লেখা বট দিয়ে ভরা যেতে পারে। সমাধান rules-এ নেই → **Firebase App Check (reCAPTCHA v3)** চালু করুন; `js/firebase-config.js`-এ `RECAPTCHA_V3_SITE_KEY` এখনো placeholder। প্রথমে "Monitor" মোডে, ট্রাফিক ঠিক দেখলে "Enforce"।
3. **শেষ অ্যাডমিন লক-আউট।** অ্যাডমিন নিজের `isAdmin` ফেরত নিতে পারে (UI সতর্ক করে) — "শেষ অ্যাডমিন" rules-এ আটকানো যায় না। হারালে Console থেকে `isAdmin:true` ফেরান।
4. **ক্যাটাগরি সিড বাধ্যতামূলক।** আলোচনা তৈরির শর্ত "ক্যাটাগরি DB-তে আছে ও active"। UI ডিফল্ট ক্যাটাগরি দেখায়, কিন্তু অ্যাডমিন একবার "ডিফল্ট ক্যাটাগরি বসান" না চাপলে পোস্ট বাতিল হয় (UI তখন নিজেই সেই বার্তা দেয়)।
5. **UI ↔ rules ছোট অমিল (নিরাপদ দিকে):** ব্লকড ইউজারের UI-তে "এডিট" মেনু দেখা যায়, কিন্তু সংরক্ষণে `permission-denied` আসে (UI-র বার্তা: "…আপনার অ্যাকাউন্টে সীমাবদ্ধতা আছে")। প্রয়োজনে UI-তে ব্লকডদের জন্য এডিট-মেনু লুকাতে পারেন — নিরাপত্তার জন্য জরুরি নয়।
6. **লিমিট ইচ্ছাকৃতভাবে UI-র চেয়ে ঢিলা:** প্রোফাইল-নাম rules-এ ১২০ (UI ৬০) কারণ Google/GitHub `displayName` লম্বা হলে লগইনের সময় প্রোফাইল তৈরি আটকাত; `bio` ৫০০ (UI ২০০) কারণ পুরোনো/মাইগ্রেট ডেটা। বুকিং-ফর্মে `maxlength` নেই — rules-এ নাম ≤১২০, বিস্তারিত ≤৫০০০ (লম্বা হলে সাধারণ "পাঠাতে সমস্যা" টোস্ট আসবে; চাইলে `index.html`-এ `maxlength` যোগ করুন)।
7. **গোপনীয়তা (নকশা অনুযায়ী):** পাবলিক আলোচনা/রিপ্লাইয়ে লেখকের `uid`, নাম, ছবি এবং `likedBy` (লাইকারদের uid) সবাই দেখে। ইমেইল/ফোন শুধু `users`-এ (নিজে + অ্যাডমিন) ও `bookings`-এ (মালিক + অ্যাডমিন)।
8. **Rules-এ সম্ভব না:** তালিকার (`features`) প্রতিটা এলিমেন্টের টাইপ যাচাই (লুপ নেই) — শুধু `list` ও সাইজ ≤৪০ যাচাই হয়; অ্যাডমিন-ছাড়া কেউ লিখতে পারে না বলে ঝুঁকি কম।
9. **অক্ষর-গণনার অনুমান:** `size()` = অক্ষর-সংখ্যা (বাইট নয়) ধরা হয়েছে, তাই বাংলা টাইটেল ১২০ অক্ষর পর্যন্ত চলে। অফিশিয়াল Emulator-এ প্রথম রানে "Bengali … chars ok" নামের টেস্টগুলো ফেল করলে এই অনুমান ভুল — জানাবেন।
10. **হার্ড-ডিলিট বন্ধ, রিপোর্টও মোছা যায় না:** আগের টেস্টে অ্যাডমিন রিপোর্ট মুছতে পারত; অডিট-ট্রেইলের জন্য এখন পারে না (Console থেকে পারবেন)।
11. **ক্যাটাগরি `createdAt`:** অ্যাডমিন বিদ্যমান ডকে পুরো `setDoc` (সিড আবার চালানো) করলে `createdAt = request.time` গ্রহণযোগ্য; আগের টেস্টের "createdAt বদলানো বাতিল" প্রত্যাশা তাই সংশোধিত।

## ৭) টেস্টের প্রকৃত ফলাফল

**যা চালানো হয়েছে (এই পরিবেশে, Node 22):**

- `npm run test:contract` → ৩৩ চেক, **৩৩ পাস**। (যাচাই: rules-এ ইচ্ছাকৃত ভুল ঢুকিয়ে ৪টা চেক ফেল করাতে পেরেছি।)
- `npm run test:offline` → **৭৭৬ সিনারিও, ৭৭৬ পাস**: anon ৫৯ · profile ৬৬ · create ৩৯ · edit ৩১ · like ৩৬ · reply ৭৪ · report ৩৪ · booking ৩০ · admin ১২৭ · content ১৯৮ · blocked ১৭ · query ১৯ · paths ২০ · malformed ২৬। প্রযোজনীয় ২০টা বিষয়ই ঢাকা (anon, সাধারণ ইউজার, প্রোফাইল/অ্যাডমিন-escalation, গেস্ট/লগইন বুকিং, অন্যের ডেটা বাতিল, আলোচনা CRUD, author-spoofing, লাইক-জালিয়াতি, রিপ্লাই-batch, রিপ্লাই-মডারেশন, ডুপ্লিকেট/জাল রিপোর্ট, অ্যাডমিন-মডারেশন, ক্যাটাগরি, ব্লকড, অজানা পাথ, কোয়েরি-সীমা, বিকৃত ডেটা, পজিটিভ টেস্ট)।

- `npm run test:mutation` → ১৯০ mutant: ১৬৮ killed; ২১টা টিকেছে কিন্তু প্রতিটাই দুই-স্তরের শর্ত (reply-ডক ↔ parent-counter পারস্পরিক যাচাই) — সেগুলোর ১০টা জোড়া-mutant (দুই দিকই সরানো) **সব killed**; ১টা সমতুল্য (explicit default-deny ব্লক সরালেও Firestore এমনিতেই deny করে); **০ অব্যাখ্যাত survivor**। মিউটেশন চালাতে গিয়ে ১০টা টেস্ট-ফাঁক পেয়ে নতুন সিনারিও যোগ করেছি।

**যা চালানো যায়নি:**

- ❌ অফিশিয়াল `npm test` (Firebase Emulator): এই পরিবেশে ইন্টারনেট নেই, তাই `firebase-tools`/`@firebase/rules-unit-testing`/emulator jar নামানো যায়নি। তাই **"অফিশিয়াল কম্পাইলার rules-ফাইলটা গ্রহণ করে" এবং "অফিশিয়াল evaluator-এ একই ফল" — এ দুটো আমি যাচাই করিনি।** সিমুলেটর আমার নিজের লেখা (rules-ভাষার যে অংশ ব্যবহৃত হয়েছে শুধু সেটুকু); অজানা ফাংশন পেলে চুপ না থেকে এরর দেয়, আর শুধু প্রচলিত/ডকুমেন্টেড ফাংশন (`get/exists/getAfter/existsAfter`, `hasOnly/hasAll/hasAny`, `diff().affectedKeys()`, `matches`, `size`, `lower`, `split`, `is`, `in`, `let`) ব্যবহার করা হয়েছে।
- অফিশিয়াল রানে যে টেস্টগুলো আগে সন্দেহ করবেন (ভিন্ন আচরণ হলে): "Bengali … chars" (অক্ষর-গণনা), "cannot list without limit" (`request.query.limit` অনুপস্থিত), anonymous-provider টোকেনের সিনারিও, `count` কোয়েরি। ১টা সিনারিও (`simOnly`) অফিশিয়াল রানে স্বয়ংক্রিয়ভাবে skip হয়।

- অফিশিয়াল Emulator-রান বাকি (ধাপ ৯.৩) — সেটা পাস না করা পর্যন্ত "প্রোডাকশন-পরীক্ষিত" বলা যাবে না।

## ৯) সেটআপ ও ডিপ্লয় (Android/Termux-বান্ধব)

> ফাইল মার্জ: ZIP-এর ফাইলগুলো প্রজেক্ট-রুটে (যেখানে `index.html`, `firebase.json` আছে) একই পাথে কপি/ওভাররাইট করুন। `assets/` ছোঁয়া হয়নি।

**৯.১ ফাইল কোথায় যাবে**
`firestore.rules` → প্রজেক্ট-রুটে (`firebase.json`-এর `"rules": "firestore.rules"` এটাই খোঁজে — পাথ বদলানোর দরকার নেই)। `js/admin.js` প্রতিস্থাপন। `tests/` ও `docs/` মার্জ।

**৯.২ লোকালি যাচাই (ইন্টারনেট/Java ছাড়াই) — Termux**
```bash
pkg update && pkg install -y nodejs-lts     # Node ≥ 18.19 লাগে (lts ঠিক আছে)
cd ~/TVS2ND-main/tests            # আপনার প্রজেক্টের পাথ
npm run test:contract             # ক্লায়েন্ট ↔ rules চুক্তি (৩৩ চেক)

```
প্রত্যাশিত: সব `# fail 0`; mutation-এ "অব্যাখ্যাত-survived 0"।

**৯.৩ অফিশিয়াল Firebase Emulator-এ টেস্ট (ডিপ্লয়ের আগে অবশ্যই)**

প্রত্যাশিত: ৭৭৫টা সিনারিও পাস + ১টা skip (sim-only) + ৩৩ contract পাস। কোনো ফেল এলে নাম ও এরর আমাকে পাঠান। Termux-এ `firebase-tools`/emulator না চললে একই কমান্ড PC, GitHub Codespaces বা Google Cloud Shell-এ চালান।

**৯.৪ Firebase Console-এ যাচাই (publish ছাড়াই)**
1. আগে বর্তমান rules কপি করে রাখুন: Console → Firestore Database → **Rules** → সব টেক্সট কপি → ফাইলে সেভ (`rules-backup.txt`)।
2. `firestore.rules`-এর পুরো লেখা এডিটরে পেস্ট করুন — লাল এরর না এলে সিনট্যাক্স ঠিক (এখনো **Publish** চাপবেন না)।
3. **Rules Playground**: ① Unauthenticated, `get`, `/tvProject/main/settings/site` → ✅ Allowed। ② Unauthenticated, `get`, `/tvProject/main/users/যেকোনো` → ❌ Denied। ③ Unauthenticated, `create`, `/tvProject/main/services/x` → ❌ Denied। (batch/`getAfter` Playground-এ চলে না — সেগুলো ৯.৩-এ কভার।)

**৯.৫ CLI দিয়ে ডিপ্লয়** (শুধু `tvsitesofficial`-এ — অন্য অ্যাপ থাকলে আগে সেগুলোর rules যোগ করুন!)
```bash
npm i -g firebase-tools
firebase login --no-localhost
firebase use tvsitesofficial
firebase deploy --only firestore:rules,firestore:indexes
```
`deploy` প্রথমে rules কম্পাইল করে — এরর থাকলে release হয় না। (আমি `firebase deploy` চালাইনি, লাইভ ডেটা/rules ছুঁইনি।)

**৯.৬ প্রথম অ্যাডমিন নিরাপদে বানানো (একবারের ম্যানুয়াল ধাপ — কোনো backdoor নেই)**
1. সাইটে নিজের অ্যাকাউন্টে সাইন-আপ/লগইন করুন (এতে `tvProject/main/users/{uid}` তৈরি হয়, `isAdmin:false`)।
2. Console → Authentication → Users → নিজের **UID** কপি।
3. Console → Firestore → `tvProject` → `main` → `users` → ওই UID-এর ডক → `isAdmin` = **boolean `true`** → Update। (Console Rules-কে এড়ায়, তাই এটাই একমাত্র "শুরুর" পথ; ক্লায়েন্ট থেকে নিজেকে অ্যাডমিন বানানো rules-এ অসম্ভব।)
4. পেজ রিফ্রেশ → প্রোফাইলে "অ্যাডমিন প্যানেল" লিংক। এরপর বাকিদের অ্যাডমিন/ব্লক করা প্যানেল → ইউজার থেকেই।
(মাইগ্রেশন করলে বিকল্প: `node migrate-to-tvproject.mjs --key ./serviceAccount.json --admin you@example.com`।)

**৯.৭ ডিপ্লয়ের পর প্রথমবারের কাজ**
অ্যাডমিন → ড্যাশবোর্ড → **"ডিফল্ট কন্টেন্ট বসান"** (কন্টেন্ট খালি থাকলে); অ্যাডমিন → কমিউনিটি মডারেশন → **"ডিফল্ট ক্যাটাগরি বসান"** (না করলে কেউ পোস্ট করতে পারবে না)।

**৯.৮ ডিপ্লয়ের পর স্মোক-টেস্ট (লগ-আউট ব্রাউজারে শুরু, ডেভটুলস কনসোলে `permission-denied` দেখুন)**
1. **পাবলিক সাইট (লগইন ছাড়া):** সার্ভিস, পোর্টফোলিও, টিম, স্ট্যাটস, প্রাইসিং, FAQ, হিরো-টেক্সট লোড হচ্ছে; কনসোলে permission-error নেই।
2. **বুকিং:** গেস্ট হিসেবে ফর্ম পাঠান → সফল টোস্ট। লগইন করে আবার পাঠান → প্রোফাইল ড্রয়ারে "আমার বুকিং"-এ দেখা যায়।
3. **লগইন:** ইমেইল/Google/GitHub — নতুন ইউজারের প্রোফাইল-ডক তৈরি (৬ ফিল্ড); নাম/ফোন/bio এডিট; ছবি আপলোড/মুছা।
4. **অ্যাডমিন প্যানেল:** ড্যাশবোর্ড-সংখ্যা; বুকিং-তালিকা ও স্ট্যাটাস বদল/ডিলিট; ইউজার-তালিকা; (টেস্ট-অ্যাকাউন্টে) অ্যাডমিন দেওয়া/নেওয়া ও কমিউনিটি-ব্লক; কন্টেন্ট যোগ/এডিট/ক্রম-বদল/ডিলিট; সেটিংস সংরক্ষণ।
5. **কমিউনিটি (সাধারণ ইউজার):** পোস্ট তৈরি; লাইক/আনলাইক; রিপ্লাই (কাউন্ট +১); রিপ্লাইয়ে "উত্তর"; এডিট; নিজের রিপ্লাই মুছা (কাউন্ট −১); রিপোর্ট (একই কনটেন্টে ২য়বার নয়)।
6. **কমিউনিটি (অ্যাডমিন):** পোস্ট/রিপ্লাই হাইড-রিস্টোর (কাউন্ট ঠিক থাকছে), রিপোর্ট থেকে সরাসরি মডারেট + resolved, ক্যাটাগরি যোগ/বন্ধ/মুছা।
7. **ব্লকড ইউজার:** টেস্ট-অ্যাকাউন্ট ব্লক করে → পোস্ট/রিপ্লাই/লাইক/রিপোর্ট ব্যর্থ; কিন্তু সাইট দেখা, বুকিং, প্রোফাইল এডিট, নিজের পোস্ট মুছা চলে।
8. **নেগেটিভ চেক:** সাধারণ ইউজার দিয়ে `admin.html` খুললে প্যানেল খোলে না।

**৯.৯ সমস্যা হলে rollback:** Console → Rules-এ `rules-backup.txt`-এর লেখা পেস্ট → Publish। (কনসোলে সমস্যা-ধরা কোয়েরি দেখতে ডেভটুলস → Console-এ `permission-denied` লাইন; কোন পাথ আটকাচ্ছে সেটা সেখানেই লেখা থাকে।)
